# 캐릭터 후보 요청 설계 (2026-09-20 · 2026-09-21 개편)

## 목표와 기준

`public/catalog/tone/1.jpg`(실사), `4.jpg`(일상 스냅), `3.jpg`(화보), `2.jpg`(시네마틱)을 직접 확인하고, 부드러운 얼굴 조명·맑은 피부 표현·단정한 한국 배우 프로필 같은 인상을 요청에 반영했다. 기존의 짧은 키워드와 일괄적인 `plain neutral background` 지시를 구체적인 장면 설명으로 바꿨다.

이 변경은 **텍스트 요청 개선**이다. 썸네일 파일 자체를 Gemini에 첨부하거나 같은 얼굴을 복제하는 변경은 아니다. 원하는 미감을 설명하되 새로운 가상 성인 캐릭터를 생성한다. 실제 개선 정도는 동일 옵션의 후속 이미지 비교가 필요하며, 이번 코드 검증에서는 유료 생성을 실행하지 않는다.

## 요청 구조 (2026-09-21 개편)

`draftPrompt()`가 **구조화된 JSON 텍스트 한 덩어리**를 만들어 기존 Gemini `input`의 text로 보낸다.
네거티브 프롬프트용 별도 API 필드나 Midjourney 전용 옵션을 추가하지 않는다.

키워드를 늘어놓는 대신 장면·인물·카메라를 필드로 나눠 서술한다. 핵심은 **고정되는 것과 바뀌는 것의 분리**다.
같은 사람을 다른 옷·조명·장소에 세워도 얼굴의 현실감이 유지되어야 하므로, 사람은 `identity_fixed`에,
연출은 `scene`·`styling`에 담는다.

```json
{
  "task":  "새 가상 한국 성인 1명. 유명인 닮음·일반화된 이상형 금지. 미성년 금지.",
  "scene": { "description": "<character_options.prompt — 톤의 매체·조명·배경>", "mood": "<vibe>" },
  "subject": {
    "identity_fixed": { "ethnicity", "gender", "age", "age_direction", "face(후보별 윤곽)", "build", "hair", "priority" },
    "presentation":   "<성별별 연출 — 아래 표>",
    "styling":        { "wardrobe": "장면에 맞는 단순한 옷, 무채색 계열", "expression": "<vibe>에 맞는 자연스러운 표정" }
  },
  "camera_technical": { "capture", "composition", "color", "retouching", "style" },   // 사진 톤(실사·시네마틱·화보·일상 스냅)만
  "rendering":        { "medium", "composition" },                                     // 애니·3D·그 외 그림 톤
  "avoid":  [ "..." ],
  "output": "한 사람, 한 장, 프레임 가득"
}
```

### 실사 어휘 — 사진 톤에만

AI 티가 덜 나는 인물 사진은 "예쁜 사람"이라고 써서 나오지 않는다. 다음 조합에서 나온다.

`photorealistic` · `natural skin texture` · `realistic facial details` · `soft diffused lighting` ·
`muted neutral color palette` · `shallow depth of field` · `Korean editorial / lifestyle photography` ·
`candid` · `understated`

`camera_technical`이 이 어휘를 싣는다. 반대로 **`beautiful` · `gorgeous` · `flawless` · `stunning` · `perfect`는
어디에도 쓰지 않는다.** 그 말이 "너무 완벽한 사람" 특유의 AI 얼굴을 만든다. 테스트가 이 금칙어를 검사한다.
애니·3D 톤은 `camera_technical` 대신 `rendering`을 받고, 피부 모공·렌즈 어휘가 들어가지 않는다.

### 성별별 연출 (`presentation`)

여성 사진에서 뽑은 원칙을 그대로 남성·중성에 쓰면 안 된다. 성별마다 무엇을 자연스럽다고 볼지가 다르다.
`prompt.ts`의 `GENDER_PRESENTATION`이 성별 옵션 id로 고른다. 모르는 id는 공통 문구로 떨어진다.

| 성별 | 특징(모든 매체) | 피부(사진 톤만) |
|---|---|---|
| 여성 | 자연스러운 한국인 얼굴, 은은한 메이크업·자연 립 컬러, 절제된 스타일링. 뷰티 필터 얼굴 금지(확대된 눈·과장된 입술·짙은 컨투어링) | 맑되 질감 있는 피부, 미세 모공, 자연스러운 톤 편차 |
| 남성 | 자연스러운 한국인 남성 얼굴, 단정한 눈썹·그루밍(나이에 맞게 면도 또는 가볍게 정리), 절제된 멘즈웨어 에디토리얼. 여성화하는 보정·과장된 턱선·보디빌더 체형 금지 | 모공이 보이는 질감, 턱 주변 자연스러운 음영과 약간의 불균일 |
| 중성적 | 의도적으로 중성적인 인상 — 어느 쪽으로도 뚜렷히 읽히지 않는 균형, 메이크업 최소, 유니섹스 스타일링. 관습적 여성·남성 틀로 되돌아가지 않기 | 미세 모공과 자연스러운 톤 편차 |

공통으로 "개인의 특징·작은 비대칭을 남긴다"를 넣는다. 매끈한 플라스틱 피부 금지도 공통이다.

### 나이·후보 차이

- 20대 초반·후반만 생기·편안한 눈가·부드러운 얼굴 볼륨을 지시한다. 30대 이상은 나이를 정직하게 표현하고
  20대로 되돌리지 않는다.
- 후보 4장은 `identity_fixed.face`만 다르다(타원형·살짝 좁아지는·둥근·각진). 나머지 필드는 4장이 완전히 같다.

## 톤별 차이

| 톤 | 핵심 요청 |
|---|---|
| 실사 | 확산된 창가 빛, 눈가의 약한 보조광, 작은 캐치라이트, 베이지 실내, 50mm 느낌, 섬세한 피부 질감 |
| 일상 스냅 | 조용한 카페 밖, 따뜻한 역광과 얼굴을 밝히는 반사광, 캐주얼 복장, 편안한 자세, 자연스러운 스마트폰 원근감 |
| 화보 | 밝은 회색 스튜디오, 큰 소프트박스와 보조광, 85mm 느낌, 절제된 뷰티 보정, 선명한 눈 |
| 시네마틱 | 블루아워 창가·도시 보케, 청색 주변광·따뜻한 가장자리 빛, 얼굴이 묻히지 않는 보조광, 은은한 그레인 |

톤 문장은 `character_options.prompt`(DB)에 있고 `scene.description`에 그대로 들어간다. 배포 없이 고칠 수 있다.
어느 톤이 사진 계열인지는 `prompt.ts`의 `PHOTOGRAPHIC_TONE_IDS`가 정한다. 사진 톤을 새로 추가하면 거기에도 넣는다.
다듬기·3방향은 새 인물을 캐스팅하는 지시를 재사용하지 않고 기존 얼굴 유지 지시문을 계속 쓴다.

## 검증과 운영 반영

`npm run test:prompts`는 네트워크나 API 키 없이 실제 프롬프트 조립과 마이그레이션의 톤 문장을 검증한다. JSON 구조, 톤별 배경 보존, 나이·성별·선택 속성 보존, 성별별 연출 분리, 금칙어 부재, 애니/3D 분리, 네 후보 차이, 편집 시 동일 인물 유지 계약을 확인한다. 이미지 품질 자체를 보장하는 테스트는 아니다.

**Git main push만으로 Supabase 코드와 DB는 바뀌지 않는다.** 운영에는 아래 순서가 필요하다.

```sh
npx supabase db push --linked
npx supabase functions deploy draft-character --project-ref alafyhejiaxukrkrmehh
```

마이그레이션 `20260920000001_portrait_tone_prompts.sql`은 기존 네 톤의 prompt만 갱신한다. 스키마·과금·모델·해상도·생성 장수는 바꾸지 않는다. 두 단계 적용 후 새로 뽑은 후보부터 새 요청을 사용하며, 이미 생성한 이미지는 그대로 남는다.

공식 참고: [Gemini 이미지 생성 프롬프트 가이드](https://ai.google.dev/gemini-api/docs/image-generation). 키워드 나열보다 장면을 서술하고, 원하는 구도·조명·질감을 구체적으로 지정하는 원칙을 적용했다.
